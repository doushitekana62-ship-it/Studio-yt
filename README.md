# AI Comic Motion Studio

An Android-first, local-first comic motion video editor built with Kotlin and Jetpack Compose.

## Current implementation

This repository currently contains the initial application scaffold:

- Android application module and Compose UI.
- Prompt input screen.
- Offline deterministic storyboard draft templates.
- Five-scene, 30-second timeline.
- Timeline validation for gaps, overlaps, invalid ranges, total duration, and aspect ratio.
- Deterministic comic-panel placeholder artwork drawn locally with Android Canvas.
- GLES camera pan/zoom/shake transforms and H.264 MP4 video-only export through Android MediaCodec/MediaMuxer.
- Export progress callbacks and unit tests for timeline and motion math.

**Important:** the storyboard generator is a deterministic template system, not an LLM. The current renderer creates stylized placeholder panels from text, not AI artwork. MP4 export is video-only; audio tracks, TTS, SFX/music mixing, project persistence, and real AI model runtimes are not integrated. Export can be saved through Android's system file picker or shared via Sharesheet. The Android encoder pipeline still requires device-level playback testing.

## Requirements

- Android Studio with JDK 17.
- Android SDK 35.
- Gradle wrapper generated by Android Studio or the Gradle CLI.

Open the project in Android Studio and sync Gradle. The Gradle wrapper JAR is not committed in this initial scaffold; Android Studio can generate it, or run `gradle wrapper` with a compatible Gradle installation.

## Offline-first design

The application does not declare the INTERNET permission and does not call a remote AI service. The current template draft works offline. Any future model download feature must be an explicit user action and separate from offline production.

## Planned implementation order

1. **Validate renderer on devices:** check MP4 playback, output dimensions, timestamps, and encoder compatibility across Android versions.
2. **Export UX:** validate Save As and Sharesheet on devices; optionally add a MediaStore gallery destination.
3. **Audio pipeline:** mux dialogue, SFX, ambience, and optional music; validate audio/video duration and clipping.
4. **Local TTS:** choose a runtime/model with Indonesian support and compatible redistribution terms.
5. **Local LLM adapter:** structured output, JSON validation, retry/repair, cancellation, and model compatibility checks.
6. **Local image generation adapter:** choose an Android-compatible runtime and model after verifying backend support, memory requirements, and license.
7. **Model manager, project persistence, recovery, device profiling, and device tests.**

## Architecture principles

- Keep UI, storyboard domain logic, model runtimes, audio, and rendering separate.
- Do not claim model or device compatibility without tests on actual hardware.
- Keep generated media and model files on-device by default.
- Use checkpoints and bounded buffers for long-running operations.
- Treat model and asset licenses as release blockers until verified.
